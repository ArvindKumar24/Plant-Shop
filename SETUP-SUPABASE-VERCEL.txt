================================================================================
 GREENLEAF PLANTS - SUPABASE + VERCEL SETUP GUIDE (Flask backend)
================================================================================
This project is a Flask e-commerce app (backend/app.py) that stores all data in
Supabase (PostgreSQL) and is deployed on Vercel as a serverless WSGI function.

  Frontend  ->  Flask /api/* endpoints  ->  Supabase Postgres (psycopg2)

You do NOT need MySQL, a local database, or Node.js. You need only:
  - Python 3.9+ (local testing only)
  - A Supabase account (free tier)
  - A Vercel account (free tier, optional - only if you deploy)


--------------------------------------------------------------------------------
PART 1 - CREATE & CONFIGURE SUPABASE
--------------------------------------------------------------------------------

1. Go to https://supabase.com and sign in.

2. Click "New project".
     - Organization: any
     - Project name:  plant-shop
     - Database password: create a strong one and SAVE IT (you need it later)
     - Region: choose the one closest to you
     - Pricing: Free
   Wait ~2 minutes for the project to be created.

3. Create the tables + seed data:
   - In the Supabase Dashboard, open "SQL Editor" (left sidebar).
   - Click "New query".
   - Copy the ENTIRE contents of the file  database/schema.sql  into the editor.
   - Click "Run".
   - Expected result: success, and the output shows inserts.
     Tables created: users, products, orders, order_items, admin_users
     Seeded: 1 admin user (admin / admin123) and 12 sample products.

   (Optional) Verify:
     - Go to "Table Editor", select "products" -> you should see 12 rows.
     - Select "admin_users" -> 1 row with username = admin.

4. Copy the connection string:
   - In the Dashboard, go to  Project Settings (gear icon) -> Database.
   - Under "Connection string" -> "URI", click "Copy".
   - If your database password was entered with URL-unsafe characters
     (@, :, /, %, etc.) they must be URL-encoded in the string. The dashboard
     gives you a button to reset the password to a URL-safe one.
   - Choose the connection type depending on where the app runs:
       * LOCAL DEVELOPMENT (running Flask on your machine):
         use the DIRECT connection (port 5432).
       * VERCEL (serverless functions): use the TRANSACTION POOLER (port 6543).
     Both already include ?sslmode=require.

   Your string looks like:
     postgresql://postgres.<PROJECT-REF>:<PASSWORD>@aws-0-<REGION>.pooler.supabase.com:6543/postgres?sslmode=require

5. THAT'S IT for Supabase. You do not need the anon/service_role keys because
   Flask connects to Postgres directly with psycopg2 (like a service role).


--------------------------------------------------------------------------------
PART 2 - RUN LOCALLY (TESTING BEFORE DEPLOYING)
--------------------------------------------------------------------------------

1. Copy the example env file:
     copy .env.example .env
   (macOS/Linux: cp .env.example .env)

2. Edit .env and set DATABASE_URL to the connection string from Part 1 step 4.
   Use the DIRECT connection (port 5432) for local testing.

3. Create a virtual environment and install dependencies:
     cd backend
     python -m venv venv
     venv\Scripts\activate        (Windows)
     source venv/bin/activate     (macOS/Linux)
     pip install -r requirements.txt

4. Start Flask:
     python -m flask --app app run        (run from inside backend/)
   Or from the project root:
     flask --app backend.app run

5. Open http://127.0.0.1:5000 in your browser.

   Quick test checklist:
     - Home page loads with products
     - /products.html -> search & filters work
     - Register a customer (Login -> Register)
     - Login, add an item to cart, place an order
     - /orders.html shows your order (status: pending)
     - /admin.html -> login admin / admin123 -> manage products, view orders,
       change order status, configure UPI QR


--------------------------------------------------------------------------------
PART 3 - DEPLOY TO VERCEL
--------------------------------------------------------------------------------

1. (Optional but recommended) Push the project to GitHub.
   Make sure .env is NOT committed (it is already in .gitignore).

2. Install the Vercel CLI (or use the web dashboard):
     npm install -g vercel

3. Run from the project root:
     vercel
   - Follow the prompts. Framework preset: OTHER.
   - The vercel.json already handles: API -> Flask function, everything else
     -> static frontend.

4. Set environment variables in Vercel:
   - In the Vercel Dashboard: Project -> Settings -> Environment Variables, OR
     during `vercel` CLI setup, add:
         Name:   DATABASE_URL
         Value:  <the TRANSACTION POOLER connection string from Part 1 step 4>
   - IMPORTANT: use the transaction pooler (port 6543) for serverless.
   - Environment: Production (and Preview / Development if you want).

5. Deploy:
     vercel --prod

6. Open the URL Vercel gives you (https://<your-app>.vercel.app) and verify:
     - Storefront loads
     - https://<your-app>.vercel.app/api/products returns JSON
     - Registration / Login / Cart / Checkout work
     - Admin panel: https://<your-app>.vercel.app/admin.html  (admin / admin123)

   Re-deploy after code changes:
     vercel --prod


--------------------------------------------------------------------------------
PART 4 - HOW THE DATABASE LAYER WORKS
--------------------------------------------------------------------------------

- backend/config.py   reads DATABASE_URL from environment / .env
- backend/database.py opens a psycopg2 connection pool to that URL and exposes
                       query(sql, params, fetchone) and execute(sql, params, get_id)
- backend/app.py      (Flask) uses those helpers for every /api/* route
- backend/server.py   is the OLD http.server version, kept for local use only.
                      Production uses backend/app.py via api/index.py.

Custom auth is preserved: passwords are SHA-256 hashed and stored in the users
table; the browser sends base64(email:password) as the Bearer token. Admin is a
separate admin_users table. No Supabase Auth is used.


--------------------------------------------------------------------------------
PART 5 - TROUBLESHOOTING
--------------------------------------------------------------------------------

| Problem                               | Fix                                                              |
|---------------------------------------|------------------------------------------------------------------|
| Database connection failed            | Check DATABASE_URL in .env / Vercel env vars. Ensure password    |
|                                       | is URL-encoded (no raw @ : / % chars).                           |
| SSL error / sslmode                   | Keep ?sslmode=require at the end of DATABASE_URL.                |
| "DATABASE_URL is not set"             | Copy .env.example to .env (local) or add the env var in Vercel.  |
| 404 on /api/...                       | Make sure api/index.py is committed and vercel.json is intact.   |
| No products shown                     | Run database/schema.sql in Supabase SQL Editor again.            |
| Admin can't log in                    | Use admin / admin123. Re-run schema to re-seed if needed.        |
| Functions timeout on Vercel           | Use the TRANSACTION POOLER (port 6543) connection string.        |
| Port 5000 busy (local)                | Run: flask --app backend.app run --port 8000                     |
